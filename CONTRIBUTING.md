# Contributing to Trail

Thanks for helping. Trail is small on purpose, so the best changes make it faster, quieter or more accurate, not bigger.

## Set up

You need macOS 26 on Apple silicon and Xcode 26.

```sh
git clone https://github.com/uneasymusings/trail && cd trail
make setup      # checks Xcode, installs XcodeGen
make test       # engine tests, about a second
make run        # debug build of the app, launched
```

The engine (`Sources/TrailCore`) is a plain Swift package. Most work happens there, and `swift build` / `swift test` are all you need. The app (`App/`) is generated by XcodeGen from `App/project.yml`. Don't commit the generated `.xcodeproj`.

### Trying things without touching your own index

```sh
swift scripts/demo/make-home.swift .demo/home      # a made-up home folder
export TRAIL_HOME=$PWD/.demo/index TRAIL_USER_HOME=$PWD/.demo/home
swift run trail scan && swift run trail ask "latest pitch deck for thermal"
```

- `TRAIL_HOME` moves the index.
- `TRAIL_USER_HOME` tells the engine which folder to treat as `~`.

### Signing

`make install` signs ad hoc, which works for everything except the widget. To build the widget, sign with your own Apple Development team:

```sh
make install TEAM=ABCDE12345
```

This writes the gitignored `App/Config/Local.xcconfig`, so your team ID never lands in a commit.

## Making changes

- Match the surrounding code: small types, plain names, and comments that explain *why*.
- Add a test in `Tests/TrailCoreTests` for engine changes. Each suite builds a throwaway home folder, so tests never see your files.
- Keep the panel instant. Nothing on the keystroke path may wait on the model. `TRAIL_PERF=1 swift test --filter SearchSpeed` times searches on a 50,000-entry index; keep them under about 20 ms for ordinary words.
- Changing how search ranks? Run `swift test --filter SearchQuality` before and after. It prints how 48 everyday questions fare against a messy made-up home folder, and fails if fewer than 90% find the right file first. When you fix a miss, add the question that exposed it.
- UI is plain system glass. ASCII motion is only for loading states, and it must respect Reduce Motion.
- If you change the schema, bump `Schema.version` and add a migration step in `Schema.migrate`.

## Recording the README GIFs

```sh
make demo
```

This builds the made-up home folder, indexes it, and plays scripted scenes from `scripts/demo/scenes/*.json` against the real app. It records them with ScreenCaptureKit (without the pointer) and writes `docs/media/*.gif`. It needs ffmpeg and Screen Recording permission for your terminal. The panel never takes keyboard focus, so you can keep typing elsewhere while it records.

A scene is a list of steps:

```json
{ "steps": [
  { "wait": 5.5, "show": true },
  { "wait": 2.8, "type": "latest pitch deck for thermal" },
  { "wait": 3.0, "key": "tab" },
  { "wait": 2.0, "hide": true }
] }
```

Keys are `down`, `up` and `tab`. `toast` can be `first-run` or `map-ready`. `sort` drives the sort panel: `show`, `hide`, `down`, `tab`, `return`, `keep`, `undo`. `map` can be `show`, `hide`, `none`, or the name of a node to hover. Scenes start about 5 s in because ScreenCaptureKit drops frames while it warms up; the script trims that part.

## Releasing

1. Update `MARKETING_VERSION` in `App/project.yml` and add a section to `CHANGELOG.md`.
2. Tag and push: `git tag -a v0.2.0 -m "Trail 0.2.0" && git push origin v0.2.0`.
3. CI tests, builds an ad-hoc-signed DMG and publishes a GitHub release.
4. Update `version` and `sha256` (`shasum -a 256 Trail-0.2.0.dmg`) in `Casks/trail.rb`, and copy it to the [homebrew-trail](https://github.com/uneasymusings/homebrew-trail) tap.

Notarizing would remove Gatekeeper's warning. It needs a Developer ID certificate and the secrets listed in `.github/workflows/ci.yml`.
